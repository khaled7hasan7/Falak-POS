# Falak POS — مرجع العمل في هذا المستودع

**ما هو:** نظام نقاط بيع عربي (RTL أولاً) لفلك تك، يخدم السوبرماركت والصيدلية والملحمة والخضار من نواة واحدة ووحدات تُفعَّل من الإعدادات.
**كيف يعمل:** PostgreSQL 16 محلي + وكيل Node/Fastify على جهاز المحل (المصدر الوحيد للحقيقة، وبقية الأجهزة عملاء له عبر LAN) + واجهة React مغلَّفة بـ Tauri. **يبيع بدون إنترنت**؛ السحابة (Supabase + خدمة `falak-cloud`) للترخيص والتحديث والمزامنة والنسخ الاحتياطي فقط.

## 2. القواعد السبع غير القابلة للكسر

1. **كل قراءة** تضيف `deleted_at IS NULL` و`tenant_id`. **لا `DELETE` فعلي** من أي API — الحذف ناعم دائماً.
2. **لا كتابة مباشرة أبداً** في `stock_levels` أو `customers.balance` أو `suppliers.balance` — التريجرات وحدها تكتبها من جداول الحركات. أي شك يُحسم بإعادة الحساب من الحركات.
3. **المال `numeric` في القاعدة و`decimal.js` في الكود** (ADR-002)؛ ممنوع `float`. الكميات تُخزَّن **بالوحدة الأساسية** في الحركات (`qty_base = qty × factor`)، وبالوحدة المختارة في أسطر الفاتورة.
4. **كل عملية مالية = transaction واحدة** تشمل التغيير + صف `audit_logs` + صف `sync_outbox`. استخدم مساعد `withAudit` — لا تكتب الثلاثة يدوياً.
5. **لا لون ولا مقاس خارج الـ tokens**؛ **لا أخضر في النظام إطلاقاً** (الحالات الإيجابية = أزرق + أيقونة ✓)؛ كل رقم/مبلغ/باركود بصنف `num`؛ خصائص CSS **منطقية فقط** (`inline-start` لا `left`).
6. **الصلاحيات تُفحص في الخادم دائماً** (403)، والواجهة تخفي فقط. الحدود الرقمية في الصلاحية (`pos.discount_line:10`) تُقرأ وتُحترم.
7. **لا انحراف صامت عن الوثائق.** أي انحراف ضروري: ADR قصير في `docs/adr/` + ذكره صراحة لخالد.

## 3. هيكل المستودع

```
apps/
  pos/        React + Vite — الكاشير والإدارة (تُبنى static وتُقدَّم من الوكيل)
  agent/      Node + Fastify — API محلي، طباعة، ترخيص، مزامنة        ← المنفذ 5111
  desktop/    Tauri 2 — النافذة والمثبّت                              (M3، فارغ)
  cloud/      Node + Fastify — falak-cloud                            (M4، فارغ)
  admin/      React — لوحة تحكم فلك                                   (M4، فارغ)
  owner/      React PWA — لوحة المالك (قراءة)                          (M5، فارغ)
packages/
  db/         Drizzle schema + migrations + seed
  ui/         tokens.css، المكوّنات، الخطوط المحلية
  core/       منطق الأعمال المشترك: الفاتورة، الخصم، الضريبة، العملات
  i18n/       ar.json، en.json، terms.{business_type}.json
  printing/   ESC/POS، ZPL                                            (M2، فارغ)
  contracts/  أنواع الـ API المشتركة (zod)
tools/        سكربتات مساعدة (تنزيل الخطوط، توليد بيانات)
docs/         الوثائق المُلزِمة + adr/
```

**المجلدات الفارغة لا تُملأ استباقياً.** لكل واحد README يذكر مرحلته.

## 4. الأوامر

```bash
pnpm i                 # تثبيت التبعيات
pnpm dev               # تشغيل الوكيل والواجهة معاً
pnpm build             # بناء الكل
pnpm lint              # ESLint
pnpm typecheck         # فحص الأنواع
pnpm test              # كل الاختبارات
pnpm format            # Prettier

pnpm db:migrate        # تطبيق الترحيلات الناقصة (يسجّلها في schema_migrations)
pnpm db:seed           # مستأجر تجريبي + 500 صنف
pnpm db:reset          # هدم القاعدة وإعادة بنائها من الصفر ثم seed

pnpm fonts:fetch       # تنزيل ملفات الخطوط إلى packages/ui/fonts (مرة واحدة)
```

نطاق واحد: `pnpm --filter @falak/db test`

## 5. بيئة التطوير على هذا الجهاز

- **Node 24** · **pnpm 10** (مثبّت في `%APPDATA%\npm`).
- **PostgreSQL 16 على المنفذ 5433** — المنفذ 5432 مشغول بنسخة PostgreSQL 18 أخرى لا علاقة لها بالمشروع، **لا تلمسها**.
- الاتصال في `.env` (انسخه من `.env.example`). CI يستخدم صورة `postgres:16` على 5432 داخل الحاوية.
- الاختبارات تعمل على قاعدة منفصلة `falak_pos_test` تُبنى وتُهدم في كل تشغيل.
